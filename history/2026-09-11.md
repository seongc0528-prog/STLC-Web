# STLC 홈페이지 프로젝트 — 2026-09-11 작업 기록

## 1. 이 세션의 목표

지금까지는 기능(인증, 푸시, Supabase 연동)만 붙이고 화면은 기본 Tailwind 회색 톤 그대로였다.
이번 세션은 **디자인**만 다뤘다. 메뉴 구조를 가져온 레퍼런스 사이트 <https://www.joych.org/>
(포항 기쁨의교회)에서 **비주얼 언어까지 추출해 디자인 시스템으로 이식**하는 것이 목표.

## 2. 레퍼런스 사이트 분석 방법

joych.org는 **Vite 기반 SPA**라 HTML에 본문이 없다. WebFetch로는 `<title>` 말고는
아무것도 안 나온다. 그래서 빌드 산출물을 직접 받아서 파싱했다.

```bash
curl -sL https://www.joych.org/ -o joych.html          # 에셋 경로 확인
curl -sL https://www.joych.org/assets/index-C1rvbl2e.css -o joych.css   # CSS 변수
curl -sL https://www.joych.org/assets/index-G0b9eNO9.js  -o joych.js    # 섹션 구성/색상
```

- **CSS** — 끝부분 `:root{}` 블록에 shadcn 스타일 토큰이 통째로 들어 있다.
- **JS** — 히어로 슬라이드 기본값, 퀵메뉴 배열, 하드코딩된 hex 색상 리터럴, `tracking-[...]`
  유틸리티 클래스를 그대로 뽑아낼 수 있다.

> 다음에 이 사이트를 다시 뜯어볼 일이 있으면 에셋 해시가 바뀌어 있을 테니
> `joych.html`을 먼저 받아 `/assets/index-*.css|js` 경로를 다시 확인해야 한다.

## 3. 구현 내용

### 디자인 토큰 — `src/app/globals.css`

Tailwind v4 `@theme` 블록으로 전부 토큰화했다.

- `--color-brand-50 ~ 900` (딥그린 스케일), `--color-cream-*`(웜 표면),

  `.btn-outline` `.btn-ghost-light` `.card` `.card-hover`
- `@utility container-page` — 공통 max-width + 좌우 패딩

> **브랜드 색을 바꾸려면 `--color-brand-*` 한 블록만 고치면 전체가 따라온다.**
> joych의 그린을 그대로 썼으므로, STLC 고유 색이 정해지면 여기만 교체하면 된다.

### 폰트 — `src/app/layout.tsx`

Geist / Geist Mono → **Noto Sans KR + Noto Serif KR + Playfair Display**.

`next/font/google`의 `subsets`에 `korean`이 없어서 한글이 빠질 위험이 있었는데,
빌드 산출물로 **실제로 포함되는지 검증**했다:

find .next/static -name "*.css" | xargs grep -l "AC00"
# → Noto Sans KR / Noto Serif KR 청크에서 unicode-range:U+AC00,U+ACE0,... 확인

한글 글리프가 정상적으로 self-host된다. `themeColor`도 `#111827` → `#1B5E20`으로 변경.

## 4. 작업 중 발견해서 고친 기존 버그

1. **다크모드에서 글씨가 안 보였다.** `globals.css`에 `prefers-color-scheme: dark` 블록이
   있어서 배경만 `#0a0a0a`로 바뀌는데, 모든 페이지가 `text-gray-900`을 쓰고 있었다.
   교회 사이트에 다크모드가 필요하지 않다고 보고 `color-scheme: light`로 고정했다.
2. **예배 시간 하드코딩.** 헤더 상단바에 "오전 10:00 / 오후 7:30"을 박아뒀는데
   DB 실제 값은 "11:00 AM / 07:30 PM"이었다. 같은 페이지 안에서 값이 어긋나는 상태.
   헤더·푸터·홈 모두 `church_info` 단일 소스에서 읽도록 수정하고, 값이 없으면 그 줄을
   렌더링하지 않게 했다.
3. `about/worship`에서 `address`와 `address_en`이 DB에 같은 영문 주소로 들어 있어
   같은 줄이 두 번 나오던 문제 → 두 값이 다를 때만 영문을 추가 표시.

## 7. 2차 피드백 반영

### 7-1. `file_url`의 정체 확인 — 이 세션에서 제일 중요한 발견

주일 설교 페이지와 주보 페이지가 **똑같은 내용을 보여주고 있었다**. 둘 다 `sermons`
테이블을 그대로 `SermonList`로 렌더링했기 때문. 어느 쪽이 잘못된 건지 정하려면
`sermons.file_url`이 설교 원고인지 주보인지 알아야 했다.

PDF를 직접 받아서 `pdftotext`로 열어 확인했다:

```
(Sydney The Lord's Church, The Uniting Church in Australia)
18-862( 2009 75)   202696
... 교역자 명단 / 예배 시간 / 광고 1~9번 ...
```

→ **`file_url`은 주보(週報)다.** 설교 원고가 아니다.
(부수 소득: "제18권 862호, **창립 2009년 7월 5일**"과, 교회 영문명에 실제로
"in Australia"가 붙는다는 것까지 이 PDF로 확인됐다.)

이어서 REST로 67건 전체를 확인:

| | |
|---|---|
| 전체 | 67건, **전부 `sunday`** (수요 예배 데이터는 0건) |
| `video_url` | **0건** |
| `file_url` | 67건 (전부 주보 PDF) |
| `summary` | 67건, 문단이 빈 줄로 구분된 **설교 전문** |

결론: 설교의 "풀 버전 문서"는 `summary` 본문이고, 주보는 `file_url`이다.
두 페이지를 이 기준으로 완전히 갈랐다.

### 7-2. 대문 문구 / 창립 연도

### 7-3. 예배 안내 줄바꿈

`about/worship`에서 수요예배의 시간이 아래로 밀려나 있었다.
**원인은 "WEDNESDAY SERVICE"가 길어서가 아니라** flex 아이템에 `min-w-0`이 없어서
왼쪽 블록이 안 줄어들고 오른쪽 시간을 밀어낸 것. `min-w-0` + `shrink-0`으로 고쳤다.
요청대로 영문 라벨에서 `SERVICE`를 빼 **Sunday / Wednesday**로 통일(대문 페이지도 동일).

### 7-4. 설교 카드와 설교 전문

- 카드 상단 초록 영역: `aspect-video` → **`h-16` 띠**(십자가 아이콘만 들어갈 높이).
  `video_url`이 들어오면 자동으로 16:9 유튜브 썸네일로 전환된다.
- 카드 전체가 **`/tv/sunday/[id]`** 상세로 연결된다. 상세에서 `summary`를 빈 줄 기준으로
  문단 분리해 설교 전문을 보여주고, 영상이 있으면 유튜브 임베드도 띄운다.
- `SermonDetail.tsx`를 주일/수요 두 라우트가 공유한다.
- 대문의 "최근 설교"도 같은 `SermonList`를 쓰도록 정리 — 중복 45줄 제거.

### 7-5. 페이지네이션

`Pagination.tsx` 신규. `?page=N` 서버 페이지네이션(supabase `.range()` + `count: 'exact'`),
현재 페이지 주변 ±2개 번호만 노출. 주일 설교 **10개씩**(67건 → 7페이지), 수요 예배 동일.

### 7-6. 주보 페이지

성격을 완전히 분리했다.

- **설교 목록/상세에서 `file_url`을 아예 select 하지 않는다** — 첨부파일 링크 제거.
- **주보 페이지는 `file_url`이 있는 건만** 조회하고, 제목도 설교 제목이 아니라
  `bulletinLabel()`이 만든 **"2026년 9월 7일 주보"** 형식의 날짜다.
- 카드마다 **pdf.js로 1페이지를 실제 렌더링한 스냅샷**을 띄운다 (`PdfThumbnail.tsx`).
- `/support/bulletin/[id]` 상세에서 iframe 뷰어 + PDF 다운로드.
  Supabase Storage 공개 URL에 `?download=<파일명>`을 붙이면 `Content-Disposition:
  attachment`로 내려온다는 걸 확인하고 `downloadUrl()`로 감쌌다.

#### pdf.js 도입 관련 메모

- `pdfjs-dist` 의존성 추가. 워커는 번들러 설정에 기대지 않도록 **`postinstall`에서
  `public/pdf.worker.min.mjs`로 복사**한다 (`scripts/copy-pdf-worker.mjs`).
- 주보 한 건이 약 800KB라 목록 전체를 받으면 무겁다. **IntersectionObserver로 화면에
  들어온 카드만** 렌더링하고, 페이지당 9건(3열 x 3행)으로 끊었다.
- `destroy()`는 `PDFDocumentProxy`가 아니라 **로딩 태스크**에 있다. 문서 쪽에 걸면
  타입 에러가 난다.
- **주보 1페이지는 가로형(841 x 595, A4 landscape)이다.** 처음엔 세로 A4(`1/1.414`)로
  틀을 잡았다가 빈 공간이 크게 생기는 걸 발견해서, 로딩 중에만 가로 비율로 자리를 잡고
  렌더링 후에는 캔버스가 실제 비율을 정하도록 바꿨다.

- pdf.js가 실제 주보를 파싱하는지 Node에서 직접 확인(2페이지, 뷰포트 계산, `destroy()`).
- Supabase Storage가 `Access-Control-Allow-Origin: *`와 `Accept-Ranges: bytes`를
  주는 것 확인 — 브라우저에서 pdf.js가 받아올 수 있다.

> **다만 캔버스에 실제로 그려지는 것은 확인하지 못했다.** 작업 환경에 브라우저 도구가
> 없어서 API 레벨까지만 검증했다. `/support/bulletin`을 직접 열어 확인이 필요하다.
> 실패하면 "미리보기를 불러오지 못했습니다" 폴백으로 떨어진다.
>
> (이후 사용자가 **설교 상세 화면**은 직접 확인했다고 알려왔다. 주보 스냅샷은 아직
> 확인 결과를 받지 못했다.)

## 9. 3차 피드백 반영

### 9-1. 성구 검색 링크 — 원래 없던 기능이었다

"성구를 눌러 구글 검색으로 연결한 건 좋은데, 글자 단위로 선택돼서 본문 일부만
검색된다"는 피드백을 받았다. 확인해 보니 **그런 링크를 만든 적이 없었다.**
`SermonDetail`의 성구는 그냥 `<span>` 텍스트였고, 코드베이스의 유일한 구글 링크는
예전부터 있던 `about/location`의 지도 링크였다.

사용자가 본 것은 **모바일 브라우저가 텍스트를 길게 눌렀을 때 뜨는 자체 선택/검색
기능**이다. 글자 단위로 잡힌 것도 그래서다.

아이디어 자체는 좋아서 실제 기능으로 만들었다. 핵심은 **클릭 대상이 한 덩어리여야
한다**는 것 — 성구 전체를 하나의 `<a>`로 묶어야 전체 문자열로 검색된다.

- `src/lib/scripture.ts` — `scriptureSearchUrl()`.
  질의어에 `"성경"`을 덧붙인다. "잠언 3:9" 같은 짧은 표기가 다른 뜻으로 읽히는 걸 막는다.
- 링크에 `whitespace-nowrap`을 줘서 줄 중간에 쪼개지지 않게 했다.
- **목록 카드의 성구는 링크로 만들지 않았다.** 카드 전체가 이미 상세 페이지 `Link`라
  그 안에 링크를 또 넣으면 중첩 앵커가 되어 마크업이 깨진다.

### 9-2. 히어로 줄바꿈

모바일에서 "나눔과 섬김과 좋 / 은 만남이 있는"처럼 **단어 중간이 끊겼다.**
자동 줄바꿈에 맡긴 게 원인. `text-balance`를 빼고 `<br>`로 직접 잡았다.

```jsx
나눔과 섬김,<br className="sm:hidden" /> 좋은 만남이 있는<br />
시드니 주님의<br className="sm:hidden" /> 교회입니다.
```

`sm:hidden`인 `<br>`은 넓은 화면에서 `display:none`이라 줄을 바꾸지 않는다.
덕분에 문자열 하나로 두 가지 배치를 만든다.

| | |
|---|---|
| 모바일 | 나눔과 섬김, / 좋은 만남이 있는 / 시드니 주님의 / 교회입니다. |
| 데스크톱 | 나눔과 섬김, 좋은 만남이 있는 / 시드니 주님의 교회입니다. |

요청받은 모바일 문구가 "나눔과 섬김**,**"이라, 데스크톱만 "섬김**과** 좋은"으로 두면
화면 폭에 따라 같은 표어가 다른 문장이 된다. **쉼표 버전으로 통일**했다
("과…과" 반복도 없어진다).

## 10. 위임목사 소개 페이지

사용자가 `src/assets/images/위임목사.jpg`(사진)와
`src/assets/docs/류성춘 목사 이력서.docx`(영문 이력서)를 넣어두고 페이지 작성을 요청했다.

### 10-1. 한/영 전환 기능은 아직 없다

"사이트가 한영 설정에 따른 보기를 지원하니 한글 번역을 넣어달라"는 요청이었는데,
확인해 보니 **그런 기능이 없다.** `layout.tsx`의 `lang="ko"`는 고정이고, DB의 `_en`
컬럼들은 한글 옆에 같이 띄우는 용도로만 쓰이고 있다(`daily-verse`, `about/location`).

그래서 **데이터는 한/영 양쪽을 다 갖추되, 지금은 한글을 본문 / 영문을 보조로** 띄운다.
나중에 토글이 생기면 같은 데이터에서 한쪽만 고르면 된다.

### 10-2. 이력서 파싱

docx는 zip이라 `word/document.xml`을 풀어서 `</w:p>`를 개행으로 바꾸고 태그를 지우면
문단이 그대로 나온다 (`scratchpad/docx.py`). 별도 라이브러리가 필요 없다.

이력을 `src/lib/pastor.ts`에 구조화했다 (`name`, `position`, `education`, `ministry`,
`teaching`, `theses`, `articles`, `ministryScope`). 기관명은 한국어 표기가 분명한 곳만
한글로 옮기고 해외 기관은 원문을 유지했다.

**이력서의 개인정보(생년월일, 자택 주소, 휴대폰 번호)는 공개 페이지에 넣지 않았다.**

#### 원문에서 발견한 문제 — 사용자 확인 필요

| 항목 | 원문 | 처리 |
|---|---|---|
| Alphacrucis 재직 | 이력서 안에서 **2012–2022(10년)** vs **2012.3–2018.9** 로 불일치 | 확인 전까지 **보수적으로 짧은 쪽(2012–2018)** |
| Karl Barth | `neo-authenticism` | 처음엔 `neo-orthodoxy`로 고쳤으나, **원문 그대로 되돌림** — 통용되지 않는 용어라도 논문 제목은 임의로 바꾸지 않는다 (한글 줄에서도 번역하지 않고 원어를 그대로 둔다) |
| Seoul Presbyterian Theological College & Seminary | 한글명 불명확 | 영문 유지 |
| Wycliffe | `Wycliff universith`, 연도 없음 | 철자만 수정, 연도 비움. D.D.를 "명예"로 쓸지 미정 |
| 기타 오타 | `Kambodia`, `lecrturer`, `indegenisation`, `Myonji/Myungji` 혼용 | Cambodia, lecturer, indigenisation, Myongji로 통일 |

### 10-3. 인사말 — 설교 67편에서 추출

"여태까지 쌓인 설교 말씀을 압축해서 목사님이 전하실 만한 핵심 멘트를 추려달라"는 요청.

`summary` 67건에서 `'...'입니다` 패턴의 소제목과 마지막 문단(결론)만 뽑아
21KB로 압축한 뒤(`scratchpad/sermons.py`) 반복 주제를 추렸다:

**은혜 → 감사 → 나눔 → 섬김 → 공동체**. 교회 표어 "나눔과 섬김과 좋은 만남"과
그대로 겹친다. 여기에 이민교회 정체성(호주 세속사회, 그리스도의 향기)을 더해 7문단으로 썼다.

문단별 출처를 `pastor.ts` 주석에 남겼다 — 지어낸 문장이 아니라 실제 설교에서 반복된
표현이라는 걸 나중에도 확인할 수 있게. 특히:

- 고린도전서 15장 9-10절("나의 나 된 것은 오직 하나님의 은혜")은 **3회 이상 등장하는
  대표 본문**이다.
- "교회는 건물이 아닙니다"는 "하나님이 교회를 세우신 목적"(대하 7:11-18) 결론 그대로.
- "행복의 크기는 소유의 크기가 아니라 감사의 크기"는 시편 136편 설교 결론 그대로.
- 예배 성구는 대문 히어로의 요 4:24와 맞췄다.

### 10-4. 배포 우선 전략

원래는 인사말을 승인받은 뒤 적용하려 했으나, 사용자가 **"목사님이 모바일로 직접 보고
판단하실 테니 적절한 디자인으로 먼저 배포하고 코멘트를 받아 고쳐나가자"**고 정했다.
교회 성도들에게 아직 홈페이지 존재를 알리기 전이라 가능한 방식이다.

그래서 인사말을 **초안 상태로 게시**했다. `pastor.ts`의 `greeting`에 "목사님 확인 전
초안"임을 주석으로 명시해 뒀다.

- 한글 본문이 길어 영문까지 이어 붙이면 모바일에서 지나치게 늘어지므로,
  **영문은 `<details>`로 접어 뒀다.**
- 관리자가 `staff` 테이블에 위임목사 행을 넣으면 이름·직분·사진·인사말(`bio`)은
  DB 쪽이 우선한다. 지금은 `staff`가 비어 있고 `.env.local`에 서비스 키가 없어
  DB에는 쓰지 못했다.
- 사진은 `next/image` 정적 임포트. 파일명이 한글이지만 Turbopack에서 문제없이
  번들된다(640px에서 43KB로 최적화되는 것 확인).

## 11. 남은 것 / 참고

- **히어로 오프닝 영상**이 아직 CSS 그라데이션이다. `page.tsx`에 주석으로 자리를 표시해
  뒀고, `<video className="absolute inset-0 object-cover">`를 넣으면 기존 오버레이가
  그대로 가독성을 잡아준다.
- **주보 썸네일을 저장하는 쪽이 낫다.** 지금은 볼 때마다 800KB PDF를 받아 클라이언트에서
  그린다. 관리자에서 업로드할 때 1페이지 이미지를 만들어 `sermons`에 컬럼으로 저장하면
  훨씬 가볍다 — STLC_Admin 쪽 작업이라 이번엔 안 건드렸다.
- **수요 예배 데이터가 0건**이다. 페이지와 상세 라우트는 만들어 뒀으니 데이터만 들어오면
  바로 동작한다.
- **`PageHero` 미적용 페이지** — `daily-verse`, `about/worship`, `tv/sunday`,
  `tv/wednesday`, `support/bulletin` 외 나머지는 아직 예전 스타일이다.
  `<PageHero title="..." href="..." />`만 붙이면 되는 수준.
- **브랜드 색** — joych의 딥그린을 그대로 썼다. STLC 고유 색으로 갈지는 결정 필요.
- **supabase 타입이 생성돼 있지 않다.** row가 전부 `any`로 들어와서
  `SermonDetail`에서 `summary`를 수동으로 좁혀야 했다. `supabase gen types`를 한번
  돌려두면 이런 게 사라진다.
- **위임목사 인사말은 목사님 확인 전 초안이다.** 성경 인용도 설교 본문에서 가져온
  것이지만 개역개정 표기와 정확히 일치하는지는 대조가 필요하다.
- **한/영 전환 기능**이 없다. `pastor.ts`, `nav.ts`, DB의 `_en` 컬럼까지 데이터는
  이미 양쪽을 갖췄으니, 토글 UI와 언어 상태만 얹으면 된다.
- **모바일 히어로 4줄 배치와 주보 스냅샷은 실제 브라우저에서 확인하지 못했다.**
  작업 환경에 브라우저 도구가 없다. 폰에서 한 번 봐야 한다.
- `src/lib/useIsStandalone.ts`의 린트 에러는 이번 범위 밖이라 손대지 않았다.
