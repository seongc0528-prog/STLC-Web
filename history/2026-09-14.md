## 2. 메뉴 재편

포항 기쁨의 교회처럼 항목마다 로그인 요구가 다르던 것을, 섹션 자체를 "누구나 / 성도"로 나눴다.
탭 이름은 후보 4안 중 사용자가 **A안**을 골랐다.

| 전 | 후 |
|---|---|
| 커뮤니티: 오늘의 말씀 · 행사 사진🔒 · 은혜 간증🔒 · 선교 소식 | **교회 소식** (Church News): 오늘의 말씀 · 행사 사진 · 공지사항 · 주보 |
| 행정지원: 교회 소식🔒 · 주보 · 자료실🔒 · 온라인 헌금🔒 | **성도 마당** (Members): 은혜 간증🔒 · 선교 소식🔒 · 자료실🔒 · 온라인 헌금🔒 |

- 탭 이름과 겹치지 않게 메뉴 "교회 소식"은 **공지사항**으로 바꿨다 (홈 섹션 제목, 관리자 메뉴도 같이).
- **URL은 그대로** (`/community/*`, `/support/*`) — 공유된 링크·푸시 링크 보존.
- 페이지 게이트(`requireUser`)와 RLS를 같이 맞췄다. 메뉴 표시만 바꾸면 페이지는 열려도
  데이터가 빈 목록으로 오거나, 반대로 막은 페이지의 데이터가 API로는 새기 때문.
  - 행사 사진: 게이트 제거. 앨범 올리기 폼은 로그인했을 때만 렌더.
  - 공지사항: 게이트 제거.
  - 선교 소식: 게이트 추가.

마이그레이션 `0009_popups_and_public_menus.sql`의 RLS 변경:
- `photo_albums` select: `authenticated and (...)` → `is_active or is_admin() or author_id = auth.uid()`
- `photo_items` select: `authenticated` → `exists(보이는 photo_albums)` — 앨범 RLS를 그대로 따르므로
  숨긴 앨범의 사진은 비로그인에게 안 보인다.
- `notices` select: `authenticated and (...)` → `is_active or is_admin()`
- `mission_news` select: `is_active or is_admin()` → `authenticated and (...)`
- `photo_comments`는 그대로 로그인 필요 (웹에서 아직 안 보여 줌).

## 3. 홈 팝업

### DB — `popups`
`title`(관리용·이미지 alt), `image_url`, `link_url`(nullable), `starts_on`/`ends_on`(시드니 기준
`date`, 종료일 비우면 계속), `sort_order`, `is_active`. 읽기는 `is_active or is_admin()`,
쓰기는 관리자만. `ends_on >= starts_on` 체크 제약.

### 홈페이지 — `src/components/HomePopup.tsx`
- 홈(`src/app/page.tsx`)이 `todayInSydney()`로 기간 필터: `starts_on <= 오늘`, `ends_on is null or >= 오늘`.
- 여러 개면 좌우 화살표 + "1 / 3", 키보드 ←/→, ESC·바깥 클릭으로 닫기, 열린 동안 body 스크롤 잠금.
- **"오늘 하루 보지 않기"** 는 `localStorage`(`stlc-popup-hidden-on` = 시드니 날짜)에만 기억.
- 처음엔 `useEffect` 안에서 `setOpen(true)`를 했다가 `react-hooks/set-state-in-effect` lint에 걸렸다.
  → `useSyncExternalStore`로 localStorage를 읽고, **서버 스냅샷은 "숨김"** 으로 둬서
  서버/클라이언트 마크업이 어긋나지 않게 했다.

### 관리자 — `src/pages/PopupsPage.tsx`
- 사이드바 맨 위 **홈 팝업**. 이미지는 `public-assets` 버킷, `accept="image/jpeg,image/png"`.
- `CrudPage`의 `FieldConfig`에 `help`(입력칸 아래 안내문) 옵션을 추가 — 링크 칸 설명에 사용.

## 4. 설치 앱에서 외부 링크 — 검토 결과

사용자 질문: "외부 링크를 넣었을 때 설치 앱에서 눌러도 괜찮은가?"

| 상황 | 사이트 안 링크 | 외부 링크 |
|---|---|---|
| 웹 브라우저 | 같은 탭 | 새 탭 |
| 설치 앱 · 안드로이드 | 앱 안에서 이동 | 크롬 창으로 열림, 닫으면 앱 복귀 |
| 설치 앱 · 아이폰 | 앱 안에서 이동 | 사파리로 열림, 앱은 보던 화면 유지 |
| 설치 앱 · PC | 앱 창에서 이동 | 기본 브라우저 탭 |

외부 주소를 설치 앱의 **같은 창**에서 열면 앱 화면 자체가 외부 사이트로 바뀌어(특히 iOS)
돌아오기 불편하다. 그래서:
- 링크 칸은 하나. `new URL(link, location.origin)`의 origin이 우리 사이트면 경로로 바꿔
  `<Link>`로 같은 창 이동 — `/support/news`로 적든 주소창 전체를 붙여넣든 같게 동작.
- 그 외는 `target="_blank" rel="noopener noreferrer"`.

  `npx supabase link --project-ref cqzbkravqkenpytjyajy`로 다시 연결.
  `migration list`에서 0001~0008 적용, 0009만 미적용 확인 후 `npx supabase db push`.
  - 이 PC엔 전역 `supabase` 명령이 없다 → **`npx supabase ...`** 로 쓴다.
  - `npx supabase db query --linked "<sql>"`로 운영 DB에 바로 SQL을 던질 수 있다 (검증에 유용).
- 운영 RLS를 `pg_policies`로 확인 — 위 2장의 정책이 그대로 걸려 있음.
- anon 키 REST 조회: `photo_albums` 22, `photo_items` 115, `notices` 45, `bulletins` 68 열림.
  `mission_news`/`testimonies`/`resources`는 0건인데 **운영 DB에도 원래 0건**이라 이것만으론
  차단 증명이 안 됨 → 정책 조회로 대신 확인.
- 비로그인 페이지 응답: 공지사항·행사 사진·주보·오늘의 말씀 200 / 선교 소식·간증·자료실·헌금 307 → `/auth/login`.

  (`playwright-core` + 시스템 Chrome, scratchpad에 설치)으로 확인 후 **삭제**(popups 0건).
  - 데스크톱 1280 / 모바일 390 모두 팝업 표시
  - 이미지 클릭 → `/support/news`, h1 "공지사항"
  - "오늘 하루 보지 않기" 후 새로고침 → 팝업 0개
- 외부 링크(새 창) 동작은 실사이트에서 따로 눌러 보지 않았다 — 코드 경로만 확인.
