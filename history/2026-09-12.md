### 3-3. 추적 — 브라우저를 실제로 띄워서 봤다

전날 로그에 "작업 환경에 브라우저 도구가 없어 HTML 텍스트 추출로만 검증"이라고
적혀 있었는데, **그 전제가 틀렸다.** 이 머신에 크롬이 설치돼 있고, Node 22에는
`WebSocket`이 내장돼 있다. 의존성 하나 없이 CDP로 실제 브라우저를 조종할 수 있다.

```bash

curl -s http://127.0.0.1:9222/json/list     # webSocketDebuggerUrl 확보
```

```js
const ws = new WebSocket(page.webSocketDebuggerUrl)   // Node 22 내장
await send('Emulation.setDeviceMetricsOverride', { width: 390, height: 844, mobile: true })
await send('Page.navigate', { url })
await ev(`document.querySelector('[aria-label="전체 메뉴 열기"]').click()`)
await send('Page.captureScreenshot', { format: 'png' })
```

있는 72px짜리 띠가 찍혔다.

그다음 `fixed` 요소의 컨테이닝 블록을 만드는 조상을 역추적하는 스크립트를 붙였다:

```js

  const cs = getComputedStyle(el)
  if (cs.transform !== 'none') …
  if (cs.filter !== 'none') …
  if (cs.backdropFilter !== 'none') …   // ← 여기서 걸렸다

}
```

```json
 "wrapperRect": { "x": 0, "y": 62, "w": 390, "h": 72 },   // 뷰포트가 아니다
 "panelRect":   { "x": 55, "y": 62, "w": 335, "h": 844 },

```

### 3-4. 진짜 원인

**헤더 바의 `backdrop-blur-md`.**

`backdrop-filter`(그리고 `transform`, `filter`, `perspective`, `contain: paint`,
`will-change: transform`)가 걸린 요소는 **그 안의 `position: fixed` 요소에 대해
컨테이닝 블록이 된다.** 드로어 오버레이가 헤더 안에 렌더링되고 있었으므로
`fixed inset-0`이 뷰포트가 아니라 **높이 72px짜리 헤더 바**를 가리켰다.

거기에 2장에서 가로 스크롤을 막으려고 넣은 `overflow-hidden`이 72px 바깥을 전부
잘라냈다. 남은 건 패널 맨 위 제목 줄뿐 — 정확히 사용자가 본 화면이다.

> **이 한 가지로 그동안의 모든 증상이 설명된다.** 세션 첫 스크린샷에서 흰 로그인 바가
> 화면 위쪽에 떠 있고 "ABOUT"이 초록 위에 번져 보였던 것도, 당시 `inset-y-0`이라
> 패널 높이가 **헤더 높이 72px**이 되어 내용이 전부 밖으로 삐져나온 결과였다.
> 처음 스크린샷을 그렇게 읽었어야 했다.

### 3-5. 수정

오버레이를 `createPortal(overlay, document.body)`로 body에 내보냈다. 헤더의
`backdrop-blur`는 디자인이므로 그대로 두고 드로어만 영향권 밖으로 뺐다.

포털은 `document.body`가 필요해 서버 렌더에서는 접어야 하는데, effect + setState 대신
기존 `useClientValue`(`useSyncExternalStore` 래퍼)를 재사용했다 — 하이드레이션 직후
렌더가 한 번 더 돌지 않고, 레포의 `react-hooks/set-state-in-effect` 규칙에도 걸리지 않는다.

```tsx
const onClient = () => true            // 모듈 상수여야 한다 (스냅샷 참조 안정성)
const mounted = useClientValue(onClient, false)
…
{mounted && createPortal(overlay, document.body)}
```

로컬 프로덕션 빌드(`next start`)에 같은 CDP 스크립트를 물려 검증:
`wrapperRect: {0,0,390,844}`, `containingBlockCulprits: []`, 전 항목 렌더 확인.

### 3-6. 남길 교훈

> **1. "안 보인다"를 들으면 무엇이 보이는지부터 묻는다.**
> 네 번째에 나온 "제목 줄은 보인다" 한마디가 세 번의 추측보다 정보량이 많았다.
>
> **2. DOM에 있고 CSS 규칙도 맞는데 안 보이면, 범인은 조상이다.**
> 이번 건은 요소 자신의 계산 스타일만 봐서는 영원히 안 나온다. 실제로
> `getBoundingClientRect()`는 정상값(844px)을 돌려줬다 — **조상의 `overflow: hidden`에
> 의한 클리핑은 rect에 반영되지 않는다.**
>
> **3. `backdrop-filter` / `transform` 이 걸린 요소 안에 `fixed` 오버레이를 두지 않는다.**
> 모달·드로어·토스트는 `createPortal`로 body에 내보내는 것을 기본값으로 삼는다.
>
> **4. 브라우저 없이 추측하지 않는다.**
> "환경에 브라우저 도구가 없다"는 전날의 전제를 검증하지 않고 물려받은 것이
> 세 번의 헛발질을 낳았다. 3-3의 CDP 스니펫은 재사용 가능하다.

### 3-7. 헛다리였지만 남긴 실제 수정

3번 시도에서 발견한 것은 증상의 원인은 아니었지만 진짜 결함이었으므로 그대로 뒀다.

`DrawerAccount`와 `AuthButtons`가 세션을 `getUser().then(...)`으로 읽으면서
**`.catch()`가 없었다.** 조회가 거부되거나 응답 없이 매달리면 드로어는 스켈레톤에서
멈추고 `AuthButtons`는 `null`을 반환한다 — 계정 영역이 통째로 비어 보인다.
설치된 앱은 신호가 나쁜 곳에서 열리는 일이 잦아 실제로 밟을 수 있는 경로다.

- `getUser()`(매번 서버 왕복) → **`getSession()`**(로컬 세션 읽기)
- `.catch()` + `.finally()`로 실패해도 로딩 해제
- 6초 타임아웃 — 프로미스가 끝내 settle되지 않아도 스켈레톤이 남지 않게

## 4. 설교 날짜 — 제목 속 괄호가 진짜 날짜였다

설교 제목이 전부 `"설교제목" (YYMMDD)` 형식이었다. 사용자 설명:
**괄호 안이 실제 설교한 주일**이고, `published_at`은 Flutter 앱에서 DB에 올린 날짜다.
목록 정렬과 카드 날짜가 전부 업로드일 기준이라 사용자에게 의미 없는 값이었다.

`scripts/fix-sermon-dates.mjs` — 기본 드라이런, `--apply`로만 반영, 멱등.

- 67건 전부 형식 일치, 건너뛴 건 0. 재실행 시 0건 변경 확인.
- `title_en`에도 같은 꼬리표가 있으면 함께 제거하도록 했으나 해당 건은 없었다.
- `251340` 같은 오타를 조용히 통과시키지 않도록 `Date.UTC` 왕복으로 실재 날짜인지 검증.
- 시각은 **시드니 주일 오전 10시**(`T10:00:00+10:00`)로 박았다. DST가 바뀌어도
  시드니 기준 같은 날짜를 유지하는 값이다.

눈에 띄는 이동: `"기도하는 교회, 선교하는 교회" (251116)`은 업로드가 12/23이라
목록 맨 위 근처에 있었는데 11/16 자리로 내려갔다.

### 부수 수정 — 표시 타임존 고정

`SermonList`/`SermonDetail`이 `new Date(x).toLocaleDateString("ko-KR")`로 그리고 있었다.
**렌더링 런타임의 타임존을 따른다** — Vercel은 UTC, 브라우저는 사용자별. 새로 넣은
값이 특정 시각이므로 일부가 하루 밀려 보일 수 있다. `date.ts`에 `formatChurchDate()`를
추가해 `timeZone: CHURCH_TIME_ZONE`(Australia/Sydney)로 고정했다.

> **근본 대책은 이 레포 밖이다.** Flutter 앱이 여전히 제목에 날짜를 붙인다. 앱에서
> 설교일을 별도 입력받아 `published_at`에 넣도록 고치는 게 맞다. 그전까지는 새 설교가
> 쌓일 때마다 위 스크립트를 다시 돌리면 된다.

### 5-2. `/install` — 그림으로 된 설치 안내

> "아이폰 유저인 지인과 같이 해보니까, 좀 더 step-by-step 이미지를 기반으로 한
> 디테일한 설명을 해야 사람 도움 없이 할 수 있겠더라고."

기기를 자동 판별해 아이폰 / 안드로이드 / 인앱브라우저 탭 중 맞는 것을 먼저 보여주고
"· 현재 기기" 표시를 붙인다. 탭은 수동으로도 바꿀 수 있다.

- **아이폰 6단계**: 사파리로 열기 → 하단 공유 버튼 → 목록 내려서 '홈 화면에 추가' →
  오른쪽 위 '추가' → **홈 화면 아이콘으로 실행** → 알림 허용.
  5번을 굵게 강조했다 — 여기서 대부분 막히고, 브라우저로 들어오면 알림이 오지 않는다.
- **안드로이드**: `beforeinstallprompt`가 잡히면 단계 위에 "지금 설치하기" 버튼이 뜬다.
- **인앱브라우저**: 카카오톡은 공식 스킴 버튼, 나머지는 메뉴 안내.
- 하단에 "잘 안 되시나요?" 3항목 (공유 목록에 항목이 없음 / 알림이 안 옴 / 그래도 어려움).

**그림은 실제 스크린샷이 아니라 손으로 그린 SVG 삽화다.** 실기기 캡처가 없었고, OS
버전마다 화면이 달라 스크린샷은 금방 낡는다. 눌러야 할 것의 위치와 모양만 남기고
페이지 하단에 "예시 그림"임을 명시했다.

> 지인분 아이폰에서 실제 캡처를 받으면 교체하는 편이 낫다.

푸터와 iOS 설치 배너("그림으로 보기")에서 링크된다.

## 6. PWA 이름 변경 팝업 — 코드 문제가 아니었다

> "'이름 업데이트 검토'라고 해서 … [앱 제거] [확인] 팝업이 떴는데 이게 뭐지?"

안드로이드 크롬이 **설치된 PWA의 `manifest.name`이 바뀌면** 띄우는 확인 절차다.
홈 화면 아이콘 이름은 신뢰의 근거라, 사이트가 몰래 이름을 바꿔 다른 앱인 척하는 것을
막으려고 사용자 승인을 받는다. 어제 커밋 `a4bbd63`에서 바뀐 값이 이제 반영된 것.
[확인]을 누르면 되고, 로그인·알림 설정은 유지된다. 한 번만 뜬다.

> 홈 화면에 표시되는 이름은 `short_name`인 **"STLC"**다(긴 영문명은 앱 정보에만 쓰인다).
> 한글 회중이 쓰는 앱에 라틴 약자가 붙어 있는 셈이라 바꿀 만하지만, 바꾸면
> **설치한 모든 사람에게 이 팝업이 한 번 더 뜬다.** 사용자 판단으로 남겨 뒀다.

## 7. 사이트맵 페이지 푸터 중복 제거

사이트맵 페이지는 본문 전체가 `NAV_SECTIONS` 링크 목록인데, 그 몇백 px 아래 푸터가
같은 목록을 다시 그렸다. 사이트맵 페이지에서만 푸터의 메뉴 칼럼을 접고 교회 정보 →
저작권 줄로 바로 잇는다.

푸터는 레이아웃에 **서버 컴포넌트**로 걸려 있어 현재 경로를 모른다. 두 칼럼을
`FooterBody.tsx`라는 얇은 클라이언트 래퍼로 옮겨 `usePathname()`이 판단하게 했다.
교회 정보는 서버에서 받은 그대로 `children`으로 흘려보낸다. 메뉴가 빠질 때
2단 그리드(`md:grid-cols-[1.2fr_2fr]`)도 함께 해제해 한쪽만 남은 여백을 없앴다.

검증: `/sitemap` 푸터 링크 3개(오시는 길·앱 설치 안내·사이트맵), `/` 푸터 링크 22개.

## 8. 위임목사 → 담임목사

목사님 확인을 거친 요청. `grep -rn "위임"`으로 전수 조사 후 9곳 전부 교체 —
`nav.ts`(헤더·드로어·푸터·사이트맵이 전부 따라온다), 홈 퀵메뉴, 페이지 제목·브레드크럼·
서명줄, `pastor.ts` 상수, 사진 파일명(`git mv`), 주석. 영문 `Senior Pastor`는 유지.

`staff` 테이블을 먼저 조회해 비어 있음을 확인했다 — 화면 값이 전부 코드 상수에서
오므로 DB 작업은 없었다.

**같이 고친 것**: 인사말 서명줄만 직분이 글자로 박혀 있고 바로 위 사진 옆 직분은
`staff` 행에서 읽고 있었다. 나중에 DB에 직분이 들어오면 한 페이지 안에서 두 표기가
어긋난다 → 서명줄도 같은 변수를 쓰게 했다.

> 12장(전날 로그)의 교훈이 또 통했다 — **이름을 바꿀 때는 `grep -rn`으로 하드코딩된
> 잔재를 먼저 찾는다.** 이번엔 서명줄과 이미지 파일명이 거기 있었다.

## 9. 브라우저에서 '알림 설정' 숨기기

> "앱에서는 권한 팝업이 잘 떠. 브라우저로 열었을 때는 앱 설치 안내로 뛰네.
> 그렇다면 브라우저에서는 '알림 설정' 자체를 안 보여주는 게 맞겠어."

원래 의도한 동작이었다(브라우저에서는 웹 푸시를 켤 수 없으니 설치 안내로 유도).
그러나 **눌러도 약속한 일을 못 하는 메뉴는 없는 편이 낫다**는 지적이 맞다.
`isStandalone`일 때만 행을 렌더링하도록 바꿨다. 설치를 권하는 역할은 바로 위
'앱 설치 안내'가 이미 맡고 있어 경로는 남는다.

| | 앱(설치본) | 브라우저 |
|---|---|---|
| 앱 설치 안내 | ✔ | ✔ |
| 알림 설정 | ✔ (권한 팝업) | 표시 안 함 |
| 로그아웃 | ✔ | ✔ |

## 10. 이번 세션에서 쓴 검증 방법

전날까지는 "HTML 텍스트 추출"이 전부였는데, 이번에 세 단계로 늘었다.

| 방법 | 쓴 곳 |
|---|---|
| `curl` + `grep`으로 **배포본 HTML** 확인 | 새 코드가 실제로 라이브인지 (3장) |
| 배포된 CSS를 받아 규칙 존재 확인 | `.h-\[100dvh\]{height:100dvh}` 생성 여부 (3장) |
| **CDP로 실제 크롬 조종 + 스크린샷** | 드로어 재현/수정 검증, 푸터, 담임목사 페이지 |

CDP 드라이버는 `C:/tmp/`에 임시로 뒀고 레포에는 커밋하지 않았다.
스니펫은 3-3에 남겼다.

## 11. 남은 것 / 참고

- **Flutter 앱이 여전히 설교 제목에 날짜를 붙인다.** 4장 참조. 앱에서 설교일을 따로
  받도록 고치기 전까지는 새 설교가 쌓일 때마다 `scripts/fix-sermon-dates.mjs`를
  다시 돌려야 한다.
- **`/install`의 그림은 SVG 삽화다.** 실기기 스크린샷으로 교체하면 훨씬 낫다.
- **`short_name: "STLC"`** — 6장 참조. 바꾸려면 설치자 전원에게 이름 확인 팝업이
  한 번 더 뜬다는 걸 감안해야 한다.
- **사이트맵 페이지 본문이 디자인 시스템 밖에 있다.** `PageHero` 없이 `text-gray-900`,
  `text-gray-600` 같은 옛 회색 팔레트를 쓴다. 7장 작업 중 눈에 띄었지만 범위 밖이라
  손대지 않았다.
- **로그인 상태의 드로어는 실제 화면으로 검증하지 못했다.** 헤드리스 브라우저에
  계정이 없어서 9장 변경은 타입체크·린트·빌드까지만 확인했다.
- **`NotificationOptIn`에도 같은 `.catch()` 누락**이 남아 있다(3-7과 같은 패턴).
  데스크톱 헤더에서만 쓰이고 실패해도 선택적 버튼 하나가 사라질 뿐이라 이번엔 뒀다.
- 전날 로그 13장의 남은 항목들(히어로 영상, 주보 썸네일 사전 생성, 수요 예배 데이터 0건,
  `PageHero` 미적용 페이지, supabase 타입 생성, 한/영 전환, 한글 행간 1.5 전면 적용)은
  **그대로 남아 있다.**
